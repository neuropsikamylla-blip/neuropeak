## O defeito, provado por execução

O TIPO E dela não existe, e não é por falta de conteúdo: **o motor não consegue expressá-lo.**
`minimo`/`maximo` comparam contra **TODOS** os produtos da questão, nunca contra os que passaram nas
outras condições:

```ts
case "minimo": case "maximo": {
  const outros = todos.map((o) => numeroDe(o, c.campo))...   // TODOS, não os filtrados
  return c.operador === "minimo" ? meu === Math.min(...outros) : ...
}
```

**Medido:** três leites — R$ 9,00 vencendo em 2027, R$ 5,00 em 2026, R$ 7,00 em 2027 — e a pergunta
*"entre os que vencem em 2027, qual é o mais barato?"* como `validade ≥ 2027` **E** `preco = mínimo`:

```
resposta clinicamente certa: o de R$ 7,00
o motor de hoje devolve:     0 produtos — a questão seria descartada como semResposta
```

Porque o mínimo global é o de R$ 5,00, que está **fora do filtro**.

## 1. A avaliação passa a ter DUAS etapas

⚠️ **Não altere `satisfaz`.** Ele é usado em todo lugar e a semântica atual está certa para o que ele
faz. A mudança é na **composição**.

Crie uma função pura:

```ts
/** Avalia condições em duas etapas: primeiro os FILTROS, depois os EXTREMOS sobre o que sobrou.
 *  É isto que torna "entre os que X, qual o menor Y" expressável. */
export function avaliarEmEtapas(
  produtos: ProdutoNaQuestao[], condicoes: Condicao[],
): { filtrados: ProdutoNaQuestao[]; atendem: ProdutoNaQuestao[] };
```

Comportamento:
1. **Separe** as condições: `minimo`/`maximo` são **extremos**; todas as outras são **filtros**.
2. `filtrados` = produtos que satisfazem **todos os filtros** (via `satisfaz`, como hoje).
3. Se não houver extremo, `atendem = filtrados` — **o comportamento de hoje, intacto**.
4. Se houver extremo, aplique-o **sobre `filtrados`**, não sobre todos: `atendem` = os de `filtrados`
   que são o mínimo/máximo **dentro de `filtrados`**.

📌 **Isto não muda nada para as questões que já existem**: hoje uma questão ou tem só filtros, ou tem
só um extremo sozinho (a `comparacao`). Nos dois casos o resultado é idêntico ao atual. **Prove isso**
— é o item 5 dos testes.

## 2. A regra de necessidade, aplicada ao filtro (regra dela)

> *"O filtro **vence em 2027** deve deixar pelo menos 2 alternativas. Só depois a comparação de preço
> deve determinar uma. Se apenas um produto vence em 2027, isso virou busca direta disfarçada."*

Em `motivoInvalidez`, para questões que tenham **pelo menos um extremo e pelo menos um filtro**:

- `filtrados.length >= 2` → senão, motivo **`"filtroNaoFiltra"`**;
- `atendem.length === 1` → a trava de resposta única que já existe, agora avaliada em etapas.

⚠️ A validação existente passa a usar `avaliarEmEtapas` no lugar de `atendeTodas` **para o cálculo de
quem atende**. Todas as demais travas (famílias, dimensões, campo oculto, quadro entrega a resposta,
`criterioRedundante` da C3…) **continuam exatamente como estão**.

⚠️ **`criterioRedundante` e o extremo:** a regra da C3 diz que cada condição isolada deixa ≥ 2. Para
uma condição de **extremo**, "isolada" não faz sentido — o extremo sempre deixa 1 por definição.
**Exclua as condições de extremo da checagem de `criterioRedundante`** e, em troca, exija
`filtrados.length >= 2`, que é a forma correta da mesma ideia. **Declare isso no relatório.**
